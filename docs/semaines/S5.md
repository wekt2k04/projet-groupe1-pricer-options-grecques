## À comprendre

1. **Le parcours du bouton** : prix de la série → rendements log → (a) σ historique = écart-type × √252 → `sigma` → prix Black-Scholes ; (b) 30 derniers rendements → LSTM → `sigma_lstm` → prix avec σ prédite. Les deux prix s'affichent côte à côte.
2. **Pas de TensorFlow dans Odoo** : le modèle est un fichier de poids (`models/lstm_vol.npz`, monté dans le conteneur) ; `src/ml.py` refait le calcul en NumPy.
3. **Chaque prévision est enregistrée** dans `cours.vol.prediction` (menu « Prévisions LSTM ») : date, horizon, σ historique, σ prévue.
4. **Écart d'horizon à assumer à l'oral** : le LSTM prévoit la volatilité des 5 prochains jours, l'option peut durer un an. On compare deux estimations de σ ; on ne prétend pas que le prix « LSTM » est meilleur.
5. **Erreurs gérées** : pas de série, moins de 31 prix, prix négatifs ou modèle absent donnent un message clair, jamais une trace d'erreur.

**Questions probables** : comment le modèle entraîné en Python arrive-t-il dans Odoo ? Pourquoi les deux prix diffèrent-ils ? Que se passe-t-il si le fichier du modèle manque ?
